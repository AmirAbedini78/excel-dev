# گزارش اصلاح و آزمون v10.10.3 — ۲۰۲۶/۰۹/۱۱

وضعیت این بسته **LOCAL-VALIDATED** است. مبنای نصب، فایل‌های دقیق v10.10.2 تحویل‌شده است؛ نسخه قبلی طبق لاگ ارسالی شما روی Windows/Docker نصب شده، اما هیچ مدل آن آزمون صلاحیت را نگذرانده است.

## نتیجه‌ای که لاگ سیستم شما ثابت می‌کند

| بررسی v10.10.2 | نتیجه |
| --- | --- |
| ساخت تصویر Docker | موفق؛ ۴۵٫۷ ثانیه |
| کل تست‌های پروژه | ۲۶۸ موفق؛ ۷٫۱۴۵ ثانیه |
| نصب و بررسی فایل‌ها / آغاز Worker | موفق؛ ۳۲ فایل |
| qwen3.5:0.8b | `provider_error` پس از شروع stream |
| qwen3:1.7b | `deadline` |
| gemma3:4b | `memory_admission`؛ درخواست به مدل ارسال نشده |
| مدل / پاسخ واقعی ERP | `DEGRADED` / `PENDING` |

حافظه قابل استفاده پیش از ارزیابی حدود ۵۰۷۰ مگابایت گزارش شده؛ این عدد کل RAM یا VRAM دستگاه نیست. از این لاگ نمی‌توان نتیجه گرفت مدل اول حتماً OOM داده یا پاسخ مدل‌ها درست شده است.

## اصلاح انجام‌شده و آزمون علت

در نسخه قبلی، تایمر و خواننده جریان HTTP هم‌زمان پاسخ را می‌بستند. با ارسال HTTP/1.1 chunked و مهلت ۰٫۱۲ ثانیه، سه بار `AttributeError` بازتولید شد؛ Gateway آن نوع خطا را با `provider_error` گزارش می‌کرد. پس از اصلاح، همان سه آزمون در حدود ۰٫۱۲ ثانیه با خطای کنترل‌شده `deadline` پایان یافتند. شواهد در `evidence/chunked-before-after.json` هستند.

این یک نقص بازتولیدشده در کد است که با خروجی شما سازگار است؛ چون traceback دستگاه در لاگ نبود، آن را اثبات قطعی علت خطای مدل اول روی دستگاه نمی‌نامیم. افزایش فرصت درخواست اول، مکث مشترک endpoint پس از timeout و گزارش جزئیات هر سناریو، بخش‌های دیگر اصلاح هستند. توضیح دقیق و هزینه زمانی آن‌ها در سند ۳۰ آمده است.

## نتایج کاندید و بسته

| بررسی | نتیجه و دامنه |
| --- | --- |
| کل آزمون‌های repository | **۲۸۱ موفق**؛ شامل تست‌های قبلی و تست‌های این اصلاح |
| تست‌های جدید بازیابی جریان | **۱۳ موفق**؛ زیرمجموعه همان ۲۸۱ آزمون |
| تست‌های کم‌حافظه نسخه قبلی | **۲۶ آزمون**؛ در مجموعه کامل حفظ شده‌اند |
| تراکنش‌های بسته | **۹ موفق**؛ بکاپ، بازگشت، تعارض، خرابی و شکست حین نوشتن |
| Python / JSON / JavaScript | کامپایل و parse موفق؛ بررسی نحوی ۸ فایل JS موجود |
| بازسازی از payload | کل مجموعه روی کاندید بازسازی‌شده نیز موفق |
| نصب و بازگشت فایل‌ها | روی کپی پایه با LF و CRLF؛ بازیابی بایت دقیق فایل‌ها و route موفق |
| آرشیو | CRC، SHA-256 و تطبیق payload با کاندید تست‌شده بررسی شده |

۱۳ آزمون جدید از HTTP واقعی روی loopback با سرور مصنوعی استفاده می‌کنند: قطع پاسخ chunked در timeout، شکست UTF-8 میان چند chunk، final جدا، قطع اتصال بدون final، انتظار header، timeout موجودی مدل، عبور خطای کنترل‌شده از Worker/Gateway، مکث مشترک میان مدل‌ها و Workerهای جدا، ادامه روی endpoint مجاز دیگر، بودجه درخواست اول/بعدی، نگه‌داشتن PASS جزئی و حذف متن خصوصی از تشخیص. همچنین اجرای CLI با شرط RequireModel، خروجی غیرموفق و حفظ حالت DEGRADED را پس از timeout/SKIPPED بررسی می‌کند. آزمون دیگر، موفقیت مدل بعدی پس از مکث محدود و شکست مدل اول را از CLI واقعی بررسی می‌کند. این آزمون‌ها LLM واقعی اجرا نمی‌کنند.

۹ آزمون بسته، منطق Python مدیریت فایل را اجرا می‌کنند. آزمون بازسازی کاندید از خود payload برای اطمینان از تحویل همان کد تست‌شده انجام شده است. اجرای متن PowerShell روی Linux شبیه‌سازی نشده؛ wrapper قبلی روی سیستم شما PASS بوده، اما wrapper و payload جدید هنوز باید در همان سیستم اجرا شوند.

## محدودیت‌های باقی‌مانده

- محیط ساخت به Docker، Ollama، PowerShell و PHP CLI دسترسی اجرایی ندارد. PHP lint/behavior اجرا نشده و release gate آن را صریحاً ناقص گزارش می‌کند. PHP/وب در این اصلاح تغییر نکرده‌اند؛ CI کامل همچنان مستقل است.
- پاسخ، زمان بارگذاری سرد/گرم، توان CPU/GPU، اوج RAM/VRAM و رفتار v10.10.3 روی دستگاه شما هنوز اندازه‌گیری نشده‌اند. هیچ ادعای سرعت بیشتر، کاهش حافظه واقعی یا قطعی‌بودن پاسخ مدل نداریم.
- فرصت ۶۰ ثانیه‌ای درخواست اول ممکن است کافی نباشد. وضعیت `DEGRADED` موفقیت مدل نیست. مکث endpoint جلوگیری از تلاش فوری است؛ توقف قطعی پردازش داخل Ollama را اثبات نمی‌کند.
- سه سناریوی صلاحیت مصنوعی، اثبات هوش عمومی، پوشش همه عملیات یا پذیرش سه پاسخ با داده واقعی ERP نیستند. گیت معنایی MVP-B باز می‌ماند و MVP C پس از آن است.
- دریافت صفر، نداشتن پرونده پرریسک و حجم خرید به‌تنهایی رتبه کیفیت تأمین‌کننده نمی‌سازند. قرارداد شواهد، مجوزها، Proposal/Approval و محاسبات مالی حفظ شده‌اند.

نصب و بازگشت: `README_FA.md` داخل بسته. برای ادامه بررسی، خروجی کامل نصاب یا فایل‌های نتیجه/تشخیص چاپ‌شده آن کافی است؛ فایل config و توکن لازم نیست.
