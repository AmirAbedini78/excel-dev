# راهنمای کوتاه بازرگانی داخلی ایران (TR-1) — ERPSMART RC1

## مسیر استاندارد تأمین‌کننده داخلی

1. **سفارش خرید (PO)** — ثبت و تأیید دوم (ایجادکننده نمی‌تواند خودش تأیید کند).
2. **رسید انبار (GR)** — فقط مقدار عملیاتی؛ موجودی افزایش می‌یابد؛ **ثبت حسابداری روی رسید انجام نمی‌شود** (بدون GRNI).
3. **فاکتور تأمین‌کننده** — فقط از مسیر تطبیق سه‌طرفه (P2P) برای کالای مشمول سیاست Fail-Closed.
4. **تأیید فاکتور** — کنترل دوم؛ سپس پیش‌نویس سند خرید حسابداری.
5. **ثبت بدهی (AP)** — `ApPostingDomain`؛ سند روزنامه Dr خرید / Cr بستانکاران.
6. **پرداخت نقد/حواله** — `ApSettlementDomain`؛ چک و صیاد چرخه جداگانه دارند و در این مسیر پذیرفته نمی‌شوند.
7. **تخصیص پرداخت به فاکتور** — مانده بدهی از روی تخصیص‌های فعال محاسبه می‌شود.

کوک‌پیت بازرگانی (`صفحه trade` → تب داخلی) همین خط زمانی را با شناسه منبع، مقدار، مبلغ **ریال (IRR)** و وضعیت نشان می‌دهد.

## کنترل‌های مهم

| کنترل | رفتار |
|---|---|
| تکرار شماره فاکتور تأمین‌کننده | کلید یکتا P2P؛ محتوای متفاوت → خطا؛ همان محتوا → idempotent |
| فاکتور بیش از مقدار پذیرفته‌شده | رد در تطبیق |
| فاکتور دستی کالایی وقتی P2P اجباری است | مسدود مگر استثنای ممیزی‌شده |
| ارز دفتر | همیشه IRR؛ تومان فقط نمایش (T4) |
| چک / صیاد | خارج از پرداخت نقدی AP این نسخه |

## ادعانامه‌های صریح (Non-claims)

- این نرم‌افزار **سامانه مؤدیان / اظهارنامه مالیاتی زنده** نیست.
- **صیاد / چک الکترونیک** به‌عنوان تسویه نقدی AP ادعا نشده است.
- **گمرک / ارز / مالیات واردات** برای بازرگانی خارجی در RC1 فعال و ثبت‌شده در دفتر کل نیستند.
- اعداد Landed Cost خارجی **گزارشی**‌اند و جایگزین بهای تمام‌شده ثبت‌شده در دفتر نیستند مگر با سیاست تأییدشده T5.

## پروفایل شرکت

همان هسته P2P/AP برای پروفایل بازرگانی و تولیدی مصرف می‌شود؛ دفتر موازی ساخته نشده است.
